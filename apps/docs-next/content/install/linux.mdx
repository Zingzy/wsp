wsp for Linux is an AppImage for x86_64 computers. The AppImage also gives you the `wsp` command line. The install line below installs both.

## Install with one line

1. Open a terminal as the user who will use wsp.
2. Run the install line. Do not put `sudo` in front of it.

   ```sh
   curl --proto '=https' --tlsv1.2 -fsSL https://usewsp.com/install | sh
   ```

3. If the line says that the computer lacks libraries, type your password when `sudo` asks for it.
4. Open a new terminal, and run `wsp --version`. It prints `wsp` and the version that you installed.

<video src="/shots/docs-install-linux.mp4" autoPlay muted loop playsInline aria-label="The install line running in a Linux terminal, then wsp --version printing the version" />

The install line does these steps:

1. It reads the latest release of [wsp-labs/wsp](https://github.com/wsp-labs/wsp/releases) from GitHub.
2. It downloads the AppImage and compares its sha256 with the sha256 that GitHub publishes for the release. If they do not match, it stops before it unpacks anything.
3. It unpacks the files that the command runs into `~/.wsp/app/<version>-install`.
4. It makes sure that the computer has the libraries that the app needs. The next section tells you more.
5. It writes the `wsp` command at `~/.wsp/bin/wsp`.
6. It puts the AppImage at `~/Applications/wsp.AppImage`.
7. It adds `~/.wsp/bin` to your `PATH` in the files that your shell reads. The table below names the files.

| Shell | Files |
|---|---|
| bash | `~/.bashrc` and `~/.profile` |
| zsh | `~/.zshrc` |
| fish | `~/.config/fish/conf.d/wsp.fish` |
| Any other shell | `~/.profile` |

The install line does not open the app.

## The libraries that the app needs

The app links GTK and some libraries beside it. A desktop computer usually has them. A server usually does not.

If libraries are missing and the computer has `apt-get`, the install line says how many are missing. Then it installs these packages with `apt-get`:

- `libgtk-3-0t64`, or `libgtk-3-0` where the computer knows no package by the first name
- `libnss3`
- `libasound2t64`, or `libasound2` where the computer knows no package by the first name
- `libgbm1`

This is the one step that asks for `sudo`. If you run the line as root, it does not use `sudo`.

If the computer has no `apt-get`, the line stops and names the missing libraries. Install them with your package manager, and run the line again.

## Install from the download

1. Download [wsp-linux.AppImage](https://github.com/wsp-labs/wsp/releases/latest/download/wsp-linux.AppImage).
2. Make the file executable with `chmod +x wsp-linux.AppImage`.
3. Open the AppImage.

The app writes the `wsp` command at `~/.wsp/bin/wsp` each time it opens. The download does not install missing libraries and does not change your `PATH`. To run `wsp` by name, add `~/.wsp/bin` to your `PATH` yourself, or run the install line once.

## How the host runs

The host is the process that keeps your projects and threads and serves the app and the command line. On Linux, the host runs as a systemd user unit at `~/.config/systemd/user/wsp-host-<tag>.service`.

- If you open the app, the app installs the unit the first time.
- If the computer has no screen, run `wsp up --service`. It installs the same unit.

systemd starts the unit now and again at every login. To keep the host running when you are not logged in, run `loginctl enable-linger`.

wsp keeps its state in `~/.wsp/state.json`. The host writes its log to `~/.wsp/host.log`.

## Install a given version or update

- To install one release instead of the latest, set `WSP_VERSION` for the `sh` that runs the line. For example: `curl --proto '=https' --tlsv1.2 -fsSL https://usewsp.com/install | WSP_VERSION=1.2.3 sh`.
- To move to the latest release, run the install line again. It replaces the files and restarts the host unit on the new version.
