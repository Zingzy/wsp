When something does not work, start with the doctor. If wsp refused something, find its message in the tables below. Each row gives the start of what wsp says and what to do.

## Run the doctor

```sh
wsp status
wsp doctor
```

`wsp status` says whether a host serves your state file and on which ports. It exits non-zero when no host runs.

`wsp doctor` proves this computer and then every computer you added, end to end. It forks nothing and bills nothing. To prove one computer, name it: `wsp doctor <computer>`. For a cloud account, that forks a live machine, which bills while it runs. `wsp doctor --local` proves this computer alone: a thread here and its reply.

## Threads

| What wsp says | What to do |
|---|---|
| this thread is working; stop its turn first | Stop the turn, then rewind. |
| stop the threads under this one first | Stop the sub-threads it names, then rewind. |
| that is the thread's latest reply, so nothing comes after it to rewind | Pick an earlier reply. |
| that reply kept no checkpoint of the files | Rewind the conversation only. |
| this thread has no rewind to undo | A turn in this folder ended since the rewind, so the undo is gone. |
| this thread's agent has not started a conversation yet, so there is nothing to ask about | Wait for the agent's first reply, then ask. |
| *Agent* takes no side question | Drop the `/btw` and send the message to the thread. |
| This thread's early turns are no longer listed, so a side question has nothing to copy | Drop the `/btw` and send the message to the thread. |
| the answer reached for a tool, and a side question runs none | Ask again, or send it as a normal message. |
| the side question came back with no words in its answer | Ask again. |
| still working: stop it first | Stop the running thread in that tree, or run `wsp thread settle --finished <id>`. |
| --branch takes a project on this computer, where wsp makes worktrees | Use `--branch` or `wsp worktree` only for a project on the computer the host runs on. |

## Adding and joining computers

| What wsp says | What to do |
|---|---|
| *folder* has no origin remote | The computer clones the repo. Push it to an `origin` remote, then add it again. |
| *server* cannot reach this computer at ... and the forward back over ssh did not stand | Run `wsp host link` and restart the host, then add the server again. Or allow TCP forwarding in the server's sshd. |
| *address* did not answer in 20s | Put both computers on one network, or link your host to the relay, then try again. |
| *address* could not be reached | Try the next `wsp join` line, or link your host to the relay. |
| that join code is not one this host is waiting for | The code is used or expired. Run `wsp add` on the host for a new one. |
| this computer is already a place in a wsp | Run `wsp leave` on this computer first. |
| joining a Linux computer needs root | Log in as root, or run the line with `sudo`. |
| another wsp host ... is already serving | Run `wsp down` first, then `wsp up --listen <address> --service`. |

## Agents and the wsp tools

| What wsp says | What to do |
|---|---|
| *Agent* has no MCP config wsp knows, so the wsp tools were not written | Run `wsp mcp install --agent <id> --json` and add the command in `server` to the agent's MCP settings by hand. |
| *Agent*: the catalog has no MCP config for it yet, so the server was not written | The same: add the command in `server` to the agent's MCP settings by hand. |

## Opening an editor

| What wsp says | What to do |
|---|---|
| No editor wsp knows is installed on this computer. | Install one of the editors that [Editor](/features/editor) lists. |
| *Editor* is not installed on this computer; pick another editor in Settings. | Pick another editor in **Settings > General**. |
| These files are on *computer*, so they open here. | That editor cannot open files over ssh. Pick VS Code, Cursor, VS Code Insiders or Zed. |
| *Path* is not in this workspace's folder, so it does not open in your editor. | wsp opens only files inside the thread's folder. |
