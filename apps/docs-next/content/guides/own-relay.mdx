# Run your own relay

The relay gives a host that no one can reach from outside an HTTPS address. wsp uses `relay.usewsp.com` unless you name another one. The relay is in the wsp repo under `infra/relay`: a Cloudflare Worker with one D1 database. Run your own when you do not want a third party to hold your relay account and the Cloudflare account that your tunnels live on.

## Before you start

You need:

- A Cloudflare account.
- A domain on that account for the relay's own address, for example `relay.example.com`.
- A GitHub account, for the OAuth app that people sign in with.
- Node, pnpm and git on the computer that you deploy from.

Decide how hosts get their names:

- With a zone, each host gets a name of its own, `<host id>.<zone>`, through a tunnel that the relay makes on your account. The relay needs a Cloudflare API token that can edit DNS in that zone.
- Without a zone, the relay makes no tunnel and calls no Cloudflare API. Each host runs a quick tunnel and gets a new `trycloudflare.com` name each time its connector starts.

Give the relay a zone that nothing else depends on. The relay writes and deletes only `<host id>.<zone>`, but its API token can write any record in that zone. Anyone who takes over the Worker or the token takes over the whole zone. A zone that also holds your mail or your main site is the wrong one.

## Step 1: Get the code

```sh
git clone https://github.com/wsp-labs/wsp.git
cd wsp
pnpm install
cd infra/relay
pnpm exec wrangler login
```

## Step 2: Make the database

```sh
pnpm exec wrangler d1 create wsp-relay
```

Copy the `database_id` that it prints.

## Step 3: Edit `wrangler.jsonc`

The file in the repo holds the values of `relay.usewsp.com`. Replace each one with yours:

| Key | Value |
|---|---|
| `routes[0].pattern` | Your relay's address, for example `relay.example.com` |
| `d1_databases[0].database_id` | The id from step 2 |
| `vars.CLOUDFLARE_ACCOUNT_ID` | The id of the Cloudflare account that the tunnels are made on |
| `vars.RELAY_ZONE` | The zone for host names, for example `example.com`. Empty for quick tunnels. |
| `vars.RELAY_ZONE_ID` | The id of that zone. Empty for quick tunnels. |

The relay uses a zone only when both `RELAY_ZONE` and `RELAY_ZONE_ID` are set.

`observability.enabled` is `true` in the file, so Cloudflare keeps the Worker's logs. The URL of the GitHub callback carries the OAuth code and state, so those are in the logs. To keep no Worker logs, set it to `false`.

## Step 4: Apply the migrations

```sh
pnpm exec wrangler d1 migrations apply wsp-relay --remote
```

This makes the tables from `infra/relay/migrations`: the accounts, the hosts, the computers that signed in, their admissions and the link codes.

## Step 5: Make a GitHub OAuth app

In GitHub, open Settings > Developer settings > OAuth Apps and make a new app:

- Homepage URL: `https://relay.example.com`
- Authorization callback URL: `https://relay.example.com/link/callback`

Keep its client id, and make a client secret. The relay asks GitHub for no scope. It keeps the GitHub user id and login, and not the token. Each person who signs in gets an account of their own, with their own hosts.

## Step 6: Make a Cloudflare API token

Skip this step for quick tunnels. With a zone, make a token in Cloudflare with these permissions:

- Account, Cloudflare Tunnel, Edit, on the account from step 3.
- Zone, DNS, Edit, on the zone from step 3 only.

## Step 7: Set the secrets

```sh
pnpm exec wrangler secret put CLOUDFLARE_API_TOKEN
pnpm exec wrangler secret put GITHUB_CLIENT_ID
pnpm exec wrangler secret put GITHUB_CLIENT_SECRET
pnpm exec wrangler secret put RELAY_SIGNING_KEY
```

Each command asks for the value. For quick tunnels, skip `CLOUDFLARE_API_TOKEN`. For `RELAY_SIGNING_KEY`, use 32 random bytes:

```sh
openssl rand -base64 32
```

The relay signs its own tokens with this key. Anyone who has it can make tokens for any account on your relay, so keep it only in the Worker.

## Step 8: Deploy

```sh
pnpm exec wrangler deploy
```

To make sure that the Worker answers, open `https://relay.example.com/link/verify` in a browser.

## Step 9: Point wsp at your relay

wsp has no setting for the relay. You name it in the command. On the computer that runs your host:

```sh
wsp host link https://relay.example.com
wsp restart
```

On each other computer that opens your host from outside:

```sh
wsp login https://relay.example.com
```

A computer that is signed in to another relay refuses the link. Run `wsp logout` on it first.
