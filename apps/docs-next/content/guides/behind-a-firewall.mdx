# A box behind a firewall

Your computer cannot reach some computers over ssh. Examples are a computer at the office behind its company's firewall, or a computer at a friend's home behind their router. Such a computer can still dial out. This guide joins it to your host from the box itself, with `wsp join`. When the box cannot reach your computer either, your host gets an address through the relay.

## Before you start

The box must have:

- Linux on `x86_64` or `aarch64`, with systemd and cgroup v2.
- Node 22 or newer, and npm.
- A root shell. `wsp join` installs the daemon as a system service.
- A way out to the internet over HTTPS, or a way to your computer on a shared network.

You also need a terminal on the box, at the box itself or through any remote screen that you already use.

## Step 1: Give your host an address that the box can reach

If the box and your computer are on the same network, skip this step. The box dials your computer's address on that network.

Otherwise, link your host to the relay. Run this on the computer that runs your host:

```sh
wsp host link https://relay.usewsp.com
```

It prints a code and a page:

```
code        ABCD-EFGH
open        https://relay.usewsp.com/link/verify
type        ABCD-EFGH on that page
Open that page and sign in to approve <name>. ...
```

Open the page, sign in with GitHub and approve the computer. The host asks the relay for a tunnel each time it starts, so restart it:

```sh
wsp restart
```

`wsp status` then shows a `public` row with your host's address, for example `https://h1a2b3c4.usewsp.com`.

## Step 2: Make a join line on your computer

Run `wsp add` with no argument on your computer:

```sh
wsp add
```

It prints the line to type on the box, once for each address that your host answers on. When the host is linked, it adds the line for the relay's address:

```
wsp add: a computer you own joins by dialing this host. On that computer, with wsp installed:
  wsp join http://192.168.1.12:4420 --code <code>
  wsp join https://h1a2b3c4.usewsp.com --code <code>      (when the host is linked to your relay)
The code is spent by the first join and stops working in 10m. ...
```

The code is the join code and the fingerprint of your host's key, in one word. It works once, for 10 minutes. Anyone who has the code in that time can join a computer to your host, so do not post it anywhere.

## Step 3: Join from the box

On the box, open a root shell, install wsp, then run the join line:

```sh
sudo -i
npm i -g @wsp-labs/wsp
wsp join https://h1a2b3c4.usewsp.com --code <code> --name office
```

`--name` is the name that the box has in your app. Without it, the box uses its host name in lower case.

The join dials each address in turn. It checks that the host proves the key that the code names, and it stops if the key is another one. When it is done, it prints:

```
office joined the wsp at https://h1a2b3c4.usewsp.com; it dials that host on its own from now on.
systemd unit wsp-place-<tag>.service is loaded; it dials again at every start
wsp leave takes this computer back out.
```

## Step 4: Set it up and start a thread

The join installs only the daemon. To give the box its tools and agents, open it in Settings > Computers on your computer and choose what goes on it, or run:

```sh
wsp add office --resume --recipe mine
```

Then add a project on the box and start a thread, as on any computer:

```sh
wsp add https://github.com/acme/api --on office
wsp run api "Read the README and run the tests."
```

## What the relay sees

The box needs no relay account and no open port. It opens a connection out to your host's address, and the relay's Cloudflare tunnel carries it to your host. The box and the host check each other's keys, then seal every frame with X25519, HKDF and AES-256-GCM. The join code and the box's report travel inside that seal. So Cloudflare and the relay's operator see only ciphertext of the box's link.

The app's own connection through the relay is another case. A Cloudflare tunnel ends TLS at Cloudflare. So when you open your host through its relay address, Cloudflare can read that connection, with the device token in it. The relay's operator holds the Cloudflare account that the tunnel lives on, and can point your host's name somewhere else.

To avoid both, put the box and your computer on one network, or [run your own relay](/guides/own-relay) on your own Cloudflare account. [What leaves your computer](/how/network) lists what the relay stores.

## Take it back out

On the box, in a root shell, run:

```sh
wsp leave
```

It asks first. It stops if work on the box is on no remote, unless you add `--force`. Then run `wsp remove office` on your computer, because your host lists the box until you remove it there.

To take your host off the relay, run `wsp host unlink` on your computer. It stops the tunnel and deletes the host's name.
