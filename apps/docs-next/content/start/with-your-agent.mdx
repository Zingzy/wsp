# Let your agent set you up

{/* Written from skills/wsp/SKILL.md (Setting a person up from nothing, and the wsp mcp install paragraph), packages/host/src/mcp-install.ts, and wsp mcp install run against a throwaway home for claude, cursor and amp. */}

Your coding agent can set wsp up for you and open your first thread. It uses the wsp tools and the wsp skill, which is a file that tells the agent how to use wsp. You give the agent both with one command.

Before you start, install wsp ([on a Mac](/install/mac) or [on Linux](/install/linux)) so that `wsp` runs in your terminal.

## Give your agent the wsp tools

1. Go to the folder of the project that you want to work on.
2. Run `wsp mcp install` with the agent's id:

   ```sh
   cd ~/code/acme
   wsp mcp install --agent claude
   ```

3. Restart the agent, so that it loads the new tools.

<video src="/shots/docs-mcp-install.mp4" autoPlay muted loop playsInline aria-label="wsp mcp install writing the wsp tools and skill for an agent" />

`--agent` takes an agent's id, for example `claude`, `codex`, `gemini`, `opencode` or `cursor`. To set up more than one agent, give `--agent` again for each one.

For any agent other than `claude`, `codex`, `gemini` and `opencode`, such as Cursor, the command writes the skill and the wsp section but not the MCP server. To give that agent the tools, add an MCP server in the agent that runs `wsp mcp`.

For `claude`, `codex`, `gemini` and `opencode`, the command writes three things:

| What | Where |
|---|---|
| The wsp MCP server | The agent's own MCP configuration, for example `~/.claude.json` for Claude Code. |
| The wsp skill | The agent's skills folder, for example `~/.claude/skills/wsp/SKILL.md`. |
| A short wsp section | `AGENTS.md` in the folder where you ran the command, and `CLAUDE.md` beside it for Claude Code. |

If you run the command again, it replaces the wsp section and leaves the rest of the file alone. To take the section out, run `wsp mcp install --agent <id> --remove`. That leaves the MCP configuration and the skill in place.

The last line that the command prints tells you what to say to the agent next.

## Ask the agent to set you up

Start the agent in the same folder, and ask it to set you up. In Claude Code, type:

```text
/wsp set up wsp for me
```

In another agent, type:

```text
Use the wsp skill and set up wsp for me.
```

The agent checks that wsp runs, records your project and opens your first thread. The thread shows in your sidebar, and you can read and answer it there. If a step goes wrong, the agent stops and tells you.

The agent can also add a computer for you. It runs `wsp add user@host`, and you pick what goes on the computer in the app. [Add your first computer](/start/first-computer) shows those steps.

Until the agent restarts, it can do the same work with the `wsp` command line.

## What stays with you

Two things are yours, and the agent cannot do them for you:

- Sign-ins. When a tool must sign in, the agent gives you a page and a code. You finish the sign-in in your own browser.
- Keys. If you pay Anthropic by the token, write `ANTHROPIC_API_KEY=<key>` in `~/.wsp/.env` yourself. On a Claude subscription, you sign in instead. Do not paste a key into the conversation.

A `sudo` password also stays with you. If a computer's `sudo` asks for one, the agent tells you where to type it: in a terminal or in the app.

## Start work from your agent

After the setup, ask the agent for work in plain words. For example:

```text
Use the wsp skill and open a thread on acme that adds a dark mode to the settings page.
```

The agent starts the thread with `wsp run`, and the thread shows in your sidebar. [Coordinating threads from an agent](/agents/coordinating) tells you more.
