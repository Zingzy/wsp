# The pull request pane

{/* Written from apps/web/src/pull-request/, packages/runtime/src/account/pull-requests.ts, wsp fix, merge, review and start in packages/host/src/verbs/workspaces.ts and packages/runtime/src/projects/start-from.ts. */}

The Pull request pane shows the pull request of a thread's branch beside the thread: its checks, reviews, comments and the merge. From it you send a failed check or a review comment back to the agent in one click. To open it, click **+** at the top of the right panel and pick **Pull request**.

<Image src="/shots/pr.webp" alt="The Pull request pane: an approved pull request with its checks passed, ready to merge." />

wsp works through the GitHub command line, `gh`, on the computer that runs wsp, and holds no GitHub token of its own. What you do in the pane goes to GitHub as you. If the pane cannot read the pull request, run `gh auth login` there.

## What the pane shows

The **Conversation** tab has a **Status** section, then the pull request's activity:

- **Checks**, where a failed check has **Ask your agent to fix**.
- **Reviews**, naming who approved or asked for changes.
- **Comments**, the unresolved comments on lines of code. You can reply, resolve and react here.
- **Base branch**, which offers a fix for conflicts or **Update from *base***.

## Send work back to the agent

**Ask your agent to fix** sends the agent the check's name, the end of its failed log and a link. It goes to the first thread of the branch's folder, the one the work started in, which is not always the thread on screen. **Send to agent** on the comments row sends the comments to the same thread. Point at one comment to send only that one.

From the command line, run `wsp fix <thread> --check "<name>"`. Without `--check`, `wsp fix` updates the branch from its base and sends the agent any conflicts to resolve.

## Review with an agent

1. Click **Review with an agent**.
2. Pick Codex or Claude as the reviewer.
3. Click **Start**.

The reviewer reads the branch and changes nothing. Its **Draft review** waits in the pane. Tick the comments to keep, pick **Comment**, **Approve** or **Request changes**, and click **Post review**. Nothing reaches GitHub until you post. Reviews work only for a project on the computer the app runs on.

From the command line, run `wsp review <link>`, then `wsp review post <thread>`.

## Merge

The merge row says **Ready to merge** or what holds the merge. Click **Merge**, and pick a method if the repository allows more than one. While checks run, **Merge when checks pass** merges once they pass. If someone pushed since wsp last read the branch, the merge fails, so no code lands that nobody saw.

An agent cannot merge. Only you can, in the pane or with `wsp merge <thread>`.

## Open a pull request

The git button in the thread's top bar opens one. See [Changes and commits](/features/changes).

## Start a thread from a link

`wsp start <link>` opens a thread from a GitHub issue or pull request, with its title, description and comments as the first message. A pull request's thread runs in a [worktree](/features/projects) on its branch, so your checkout does not move.

The command line reference has every flag: [fix](/reference/cli/fix), [merge](/reference/cli/merge), [review](/reference/cli/review), [review post](/reference/cli/review-post) and [start](/reference/cli/start).
