# Projects and worktrees

A project is a repository or a folder on one of your computers, and threads run in its folder. The same repository on two computers is two projects. Several threads can share one project folder. To give a thread a folder of its own, run it on a branch in a worktree.

## Add a project

In the app, open **Settings > Projects** and click **Add a project**. Search your repositories or type a path, then click **Add**. To clone a repository, give its address and pick an empty folder, such as `~/code/lab`.

From a terminal, `wsp add` takes a folder, a repository address, or `owner/repo`:

```sh
wsp add ~/code/lab
wsp add acme/lab --into ~/code/lab
wsp add https://github.com/acme/lab --on studio
```

| Flag | What it does |
|---|---|
| `--into <folder>` | Clones the repository into this empty folder on the computer the app runs on. |
| `--on <computer>` | Makes the project on another of your computers, which clones the repository there. |
| `--name <name>` | Names the project. Without it, the project takes the last word of the folder or the repository. |
| `--base <branch>` | The project's base branch. Without it, the remote's default branch. |

When you add a folder with `--on`, wsp first prints the git-ignored files that go with it, such as `.env`, and sends nothing. Run the line again with `--yes` to send them. `--keep <path>` adds a path and `--cut <path>` leaves one out. See [what an imported project carries](/features/add-a-computer#what-an-imported-project-carries).

`wsp projects set <project>` sets the agent, model, effort and access a new thread there starts with. `wsp projects remove <project>` takes the project out of wsp and leaves its folder.

## Run a thread on a branch

`wsp run --branch` runs a thread on a branch other than the one the project folder has checked out:

```sh
wsp run lab --branch fix/login "Fix the flaky login test."
```

If no worktree has that branch checked out, wsp makes one. A new branch starts from the project folder's current commit. To make a worktree without a thread, run `wsp worktree <project> <branch>`, which prints its path.

`--branch` and `wsp worktree` work only for a project on the computer the app runs on.

The app has no branch picker. To work on another branch from the app, check it out in the terminal.

## What a new worktree carries

A new worktree starts with your git-ignored local files from the project folder, such as `.env`, `.envrc` and `.npmrc`. It also carries in the project folder's dependency folders and runs the locked install once, so the thread can build and test right away:

{/* generated: ecosystems */}

| Ecosystem | Lockfile | Carried in | Never carried | Install that runs |
|---|---|---|---|---|
| `npm` | `package-lock.json`, `npm-shrinkwrap.json` | `node_modules` | `.next`, `.turbo`, `.cache` | `npm install --no-save --prefer-offline --no-audit --no-fund` |
| `pnpm` | `pnpm-lock.yaml` | `node_modules` | `.next`, `.turbo`, `.cache` | `pnpm install --frozen-lockfile --prefer-offline` |
| `yarn` | `yarn.lock` | `node_modules`, `.yarn/cache`, `.yarn/unplugged` | `.next`, `.turbo`, `.cache` | `yarn install --frozen-lockfile` |
| `bun` | `bun.lock`, `bun.lockb` | `node_modules` | `.next`, `.turbo`, `.cache` | `bun install --frozen-lockfile` |
| `composer` | `composer.lock` | `vendor` | None | `composer install --no-interaction` |
| `uv` | `uv.lock` | None | `.venv` | `uv sync --locked` |
| `poetry` | `poetry.lock` | None | `.venv` | `poetry install --no-interaction` |
| `cargo` | `Cargo.lock` | None | `target` | `cargo fetch --locked` |
| `go` | `go.sum` | None | None | `go list -mod=readonly -deps -test ./... > /dev/null` |

{/* end generated: ecosystems */}

None of these installs rewrites a tracked lockfile. An install you run later in the project folder does not reach a worktree that already exists.

To run your own setup in each new worktree, set it with `wsp projects set <project> --after-worktree "<command>"`. If it fails, wsp reports it and the thread starts anyway.

## Remove a worktree

wsp removes a worktree it made once the branch's pull request is merged or closed, or the branch is deleted on the remote. It keeps the worktree while a turn runs in it or while `git status` there shows a changed or untracked file, so it never deletes uncommitted work. Files that git ignores, such as `.env`, go with the worktree.

To remove a worktree now, run:

```sh
wsp worktree remove lab fix/login
```

The branch stays. If the worktree holds files that no commit has, add `--force` to delete them with it. wsp never removes a worktree it did not make.
