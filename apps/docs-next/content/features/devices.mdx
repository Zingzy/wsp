# Other devices

Your host is the wsp process that holds your threads and serves the app, usually on your Mac. A browser on another computer, or a phone, can pair with it and open the app. Another computer with the `wsp` command line can sign in to your account and run commands against it.

## Sign in to your account

Your account is at the relay, a service that gives your host an https address. You sign in with GitHub, from the command line. **Settings > Account** shows whether this wsp is signed in. On the computer you want to sign in, run:

```sh
wsp login
```

It prints a `word`, a `code`, and a sign-in page. Then pick one:

- If another computer of yours is signed in already, run `wsp login <word>` on that computer. This signs the new computer in, and admits it to every host that trusts that computer.
- If none is, open the page, sign in with GitHub, and type the code. This admits the computer to no host. To admit it, run `wsp login <id>` on a computer that is already in.

`wsp login` alone lists the account's computers and their ids. `wsp logout` signs this computer out, and `wsp logout <id>` signs another one out.

## Reach the host from another device

### On your own network

The host that the Mac app starts listens only on the Mac. To let your network reach it, start it again as a service on an address:

```sh
wsp down
wsp up --listen <address> --service
```

### From anywhere

On the host's computer, put the host on the relay:

```sh
wsp host link
```

On a computer that is not signed in, run `wsp host link <url>` with the relay's address, then approve the code it prints. No port has to be open. See [Computers behind a firewall](/features/behind-a-firewall).

## Pair a browser or a phone

1. On the computer that runs the host, run `wsp host pair` in a terminal. It prints a code and the addresses to open.

   ```sh
   wsp host pair
   ```

2. On the other device, open one of those addresses in a browser. The page says **Pair this browser**.
3. Type the code in **Pairing code** and click **Pair**.

The code works once. Only a terminal on the host's own computer can make one, since a code lets a device in.

## See and revoke devices

**Settings > Devices** lists every paired device. To take one out, click **Revoke** beside it. It cannot reach your wsp until it pairs again.

From the command line, `wsp host devices` lists the same devices, and `wsp host devices revoke <id>` takes one out.

## Run commands against a host on another computer

Once a computer is admitted, `wsp hosts` lists every host on your account that it can reach, and marks the default. To run one command against another host, add `--host` with its name:

```sh
wsp threads --host studio
```

To use one host for a whole shell, set `WSP_HOST` to its name. With no host named, a command goes to the host on this computer, or else to the one host on your account.

The command line reference has every flag: [host pair](/reference/cli/host-pair), [host devices](/reference/cli/host-devices), [host link](/reference/cli/host-link), [login](/reference/cli/login), [logout](/reference/cli/logout) and [hosts](/reference/cli/hosts).
