# Agents and sign-ins

An agent is the coding agent a thread runs, such as Claude Code or Codex. wsp runs the agent's own command line on the thread's computer, with its own sign-in, config and sessions. Four of the agents below run threads today. The others show in the Agents pane, but cannot run a thread yet.

| Agent | Command | Runs threads | How it signs in | Key in the environment |
|---|---|---|---|---|
| Claude Code | `claude` | Yes | With a token you make, from `claude setup-token` | `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` |
| Codex | `codex` | Yes | On a page, with a device code, from `codex login` | `OPENAI_API_KEY` |
| Gemini CLI | `gemini` | No | With a code you paste back, from `gemini --skip-trust` | `GEMINI_API_KEY` |
| OpenCode | `opencode` | Yes | In its own terminal, where it asks you to pick, from `opencode auth login` | None |

| Hermes Agent | `hermes` | No | In its own terminal, where it asks you to pick, from `hermes auth` | None |

A new thread runs Claude Code unless you pick another agent. To change that default, open **Settings > Agents** and set **Default agent** under **New threads**, or run `wsp agents default <agent>`. A project can name its own agent with `wsp projects set <project> --agent <agent>`.

## The Agents pane

With the right panel open, press `A`, or pick **Agents** in the panel's launcher. The pane has three tabs: **Agents**, **Tool servers** and **Skills**.

<Image src="/shots/agents.webp" alt="The Agents pane: the agents on this computer with their versions and sign-in states, and the agents available to install" caption="The Agents pane for the computer the thread runs on." />

The **Agents** tab lists the agents on the thread's computer, each with its version and one of these states:

| State | Meaning |
|---|---|
| Signed in | The agent's own login works. |
| Your key | The agent reads a key you gave wsp. |
| Needs sign-in | The agent has no login and no key. |
| Not checked | wsp has not asked the agent yet. |

The pane does not install agents. To put one on a computer you added, use [Add a computer](/features/add-a-computer). On your Mac, install it the way its maker says.

Each installed agent shows **Sign in** until it is signed in, then **Open in terminal**. **Add the wsp tools** writes the wsp MCP server and skill into the agent's config, so the agent can drive wsp. It works for Claude Code, Codex, Gemini CLI and OpenCode, on the computer the app runs on. See [Give your agent the wsp tools](/agents/tools).

**Settings > Agents** shows the same lists for any of your computers, and a page per agent for its defaults and how it runs.

## Sign in

wsp starts the agent's own login and shows it to you. It never asks for your password. A sign-in belongs to a computer, so every thread on that computer uses it.

- If the agent works in your terminal, it works in wsp on that computer.
- In the Agents pane, click **Sign in** beside the agent. For a token or a key, wsp asks you to paste it.
- In a terminal, run `wsp agents signin <agent>`.
- On a computer you added, run `wsp add <computer> --sign-in <agent>`, or click **Sign in** on its row in **Settings > Computers**.

Claude Code has no login for wsp to run, so the two commands do not work for it. Give wsp a token instead, as the next section says.

## Keep a key in wsp's vault

To give wsp a token or a key instead of a login, run this at the host's own terminal:

```sh
wsp agents key claude
```

wsp asks for the key and does not echo it. For Claude Code, run `claude setup-token` in another terminal and paste the token it prints. An Anthropic API key does not work there. Codex, Gemini CLI and Cursor take their API key. The key stays in `~/.wsp/.env` on your host, readable by you alone, and each turn gets it as the variable in the table above.

## From the command line

| Command | What it does |
|---|---|
| `wsp agents` | Lists each agent with its version, the newest version, its sign-in, and whether it has the wsp tools. |
| `wsp agents default <agent>` | Sets the agent a new thread runs when neither the command nor its project names one. |
| `wsp agents set <agent>` | Sets an agent's default model, effort and access, and which models the pickers show, on every computer. |
| `wsp agents setup <agent>` | Sets how the agent runs on one computer: its program, its config folder, its arguments and its environment. |
| `wsp agents signin <agent>` | Runs the agent's own login in this terminal. Refused for an agent with no login, such as Claude Code. |
| `wsp agents key <agent>` | Puts a token or a key into this host's vault. For Claude Code, only a `claude setup-token` token. |
| `wsp agents addtools <agent>` | Writes the wsp MCP server and skill into the agent's config on this computer. |

Each command has its page under [Command line](/reference/cli), with every flag.
