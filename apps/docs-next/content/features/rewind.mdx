# Rewind

{/* Written from apps/web/src/actions/threadActions.ts, apps/web/src/components/chat/RewindDialog.tsx, the rewind lines in packages/protocol/src/words/thread.ts, packages/runtime/src/threads/sessions.ts, daemon/crates/wsp-daemon/src/git/checkpoint.rs. */}

A rewind takes a thread back to one of its earlier replies. The turns after that reply leave the conversation, and if you ask, the files go back to how they stood at that reply too. Use it when the agent went the wrong way and you want to try again from a point that was right.

<Image src="/shots/docs-rewind.webp" alt="A thread of three turns, with the Rewind to here button under an earlier reply." />

After each turn, wsp saves a checkpoint of the thread's folder: every file, untracked ones too, but not the files git ignores. The folder must be a git repository. A checkpoint never moves your branch, your index or `HEAD`, and a rewind makes no commit.

## Rewind a thread

1. Stop the thread's turn if one runs. A rewind never stops a turn for you.
2. Find the last reply of the turn you want to keep, and click **Rewind to here** under it, the curved arrow.
3. If the dialog asks **What goes back**, pick one:
   - **Conversation only** takes the later turns out of the conversation and leaves the files. This is the default.
   - **Conversation and files** also puts the files back to how they stood at that reply.
4. Read the note in the dialog. It says how many turns leave and what happens to the files.
5. Click **Rewind**.

The button shows under each finished turn but the latest. If a turn kept no checkpoint, **Conversation and files** is not offered.

## Undo a rewind

You can undo a rewind only if it moved files. Right-click the thread in the sidebar and click **Undo rewind**. The files come back, but the turns the rewind cut do not. Undo works until the next turn in the same folder ends.

## Threads that share a folder

A checkpoint holds the whole folder. If another thread ran a turn in the folder after the reply you picked, wsp puts back the conversation only and leaves the files, so a rewind never takes back another thread's work. It does take back edits made outside a turn since that reply, such as your own.

wsp refuses an undo while another thread works in the folder, because the undo would put back the files that thread is writing. Let its turn end or stop it, then undo.

## What each agent does

| Agent | Conversation | Files |
|---|---|---|
| Claude Code | Cut at the reply you picked | Go back |
| Codex | Cut at the reply you picked | Go back |
| OpenCode | Stays whole | Go back |
| Cursor | Stays whole | Go back |

OpenCode and Cursor keep their own history, so a rewind there puts back the files only. If another thread worked in the folder since that reply, wsp refuses the rewind for them. A Codex thread started on a Codex older than 0.151.0 gets its files back only. Update Codex to rewind the conversation too.

## The slate

A rewind also takes the thread's [slate](/features/slate) back to how it stood at that reply, or empties it if the thread had none then. Undo rewind does not bring the slate back.

Rewind is in the app only. There is no `wsp` command for it.
