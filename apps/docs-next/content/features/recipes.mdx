# Recipes

A recipe is a saved set of picks from [Add a computer](/features/add-a-computer): the agents, MCP servers, CLIs, skills, plugins, projects and config that go on a computer. With a recipe, the next computer you add starts from the same picks, and a computer that follows a recipe gets each later change to it by itself.

A recipe never holds a secret. It says how each agent and GitHub sign in, but holds no key and no token.

## Save a recipe

On the last step of Add a computer, tick **Save as a recipe**, and give it a name and an icon. The computer you add then follows that recipe.

From a terminal, save the picks of a computer you already added:

```sh
wsp recipes save build-box --from studio
```

The computer follows the recipe from then on. A recipe that already has that name is replaced. You cannot save a recipe from the computer the app runs on.

## Use a recipe

When you have a saved recipe, Add a computer shows a **Start from** step after **Checks**. Pick the recipe, and every step starts with its picks ticked. You can still change any step. The new computer follows the recipe only if you also tick **Save as a recipe** on **Summary**, or add it with `--recipe`.

From a terminal, add a computer with a recipe:

```sh
wsp add root@203.0.113.7 --recipe build-box
```

A computer you already added can follow a recipe too. Open its page in **Settings > Computers** and pick the recipe under **Follows a recipe**, or run:

```sh
wsp computers set studio --recipe build-box
```

`--recipe none` stops following. The computer keeps what it has.

## Change a recipe

Open **Settings > Recipes** and click a recipe. Its page shows the computers that follow it and its ticked rows under **Agents**, **MCP servers**, **CLIs** and **Skills**. A change to a tick saves the recipe at once.

A recipe also changes when the files it names, such as skills, configs and MCP servers, change on the computer the app runs on.

Each computer that follows a recipe puts a change on soon after. Until then, the STATE column of `wsp computers` says `Behind` for it. If you take a row out of a recipe after you edited its file on a computer, the file stays there and wsp stops managing it.

You can rename a recipe only while no computer follows it.

## Delete a recipe

On the recipe's page, click **Delete** and confirm. Or run:

```sh
wsp recipes remove build-box
```

The computers that followed it keep what it put there, and follow no recipe from then on.

## From the command line

| Command | What it does |
|---|---|
| `wsp recipes` | Lists your recipes and the computers that follow each. |
| `wsp recipes show <name>` | Shows one recipe whole, row by row. |
| `wsp recipes save <name> --from <computer>` | Saves what a computer was set up with as a recipe. The computer follows it from then on. |
| `wsp recipes remove <name>` | Takes a recipe away. Add `--yes` to skip the question. |

See [`wsp recipes`](/reference/cli/recipes) and the pages beside it for every flag.

`wsp recipe` and `wsp recipe scan` are different commands. They build the recipe of your image for `wsp init`.
