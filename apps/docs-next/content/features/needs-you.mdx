# Needs you: prompts and questions

A thread needs you when its agent stops to ask you something. A permission prompt asks before the agent runs a command or edits a file. A question asks you to pick or type an answer. The turn waits until you answer, and its turn line says "Waiting for you".

## Pick an access mode

A new thread starts in its agent's mode that asks nobody, so it never stops on a permission prompt until you pick a mode that asks. The access picker under the composer lists the agent's own modes:

| Agent | Modes in the picker | Default |
|---|---|---|
| Claude Code | Default, Accept edits, Bypass, Auto, Manual, Don't ask | Bypass |
| Codex | Read only, Workspace write, Full access | Full access |
| OpenCode | Auto | Auto |
| Cursor | Default, Force | Force |

For Claude Code, **Default** asks about each action that needs permission, and **Manual** asks before every action.

The command line, **Settings > Agents** and a project's settings use four words instead, and wsp turns each into the agent's mode:

| Word | What the agent does | Agents that take it |
|---|---|---|
| `ask` | Asks about each action that needs permission. | Claude Code, Codex |
| `auto-edit` | Edits files without asking, and asks about the rest. | Claude Code |
| `full` | Runs every action without asking. | Claude Code, Codex, OpenCode, Cursor |
| `plan` | Reads and proposes. It changes nothing. | Codex, Cursor |

## Answer a prompt

The prompt takes the place of the composer. It shows what the agent wants to do: the command, the file or the edit.

<Image src="/shots/docs-prompt.webp" alt="A permission prompt in place of the composer: the command the agent wants to run, with Allow and Deny" caption="A permission prompt. The agent waits on your answer." />

- **Allow** lets the call run.
- **Deny** refuses it and opens a field, "What to do instead", where you tell the agent what to do next.
- Some agents offer more, such as **Allow, then** a mode for the rest of the turn.

A number key picks an option and Enter answers. Esc folds the prompt away so you can read the thread.

## Answer a question

A question shows in the same place as a prompt, as a list of choices. The last choice, **Other**, opens a field for your own answer. A form with several questions has **Back**, **Next** and **Answer**.

If you fold a question away, a row above the composer says "Waiting for you". Click it to open the question again.

## The Needs you inbox

**Needs you** in the sidebar lists every thread that asks you something, at any depth of a tree, and every thread that failed and does not resume by itself. A sub-thread there wears a small ↳ arrow and shows the title of the thread that started it. A thread leaves the inbox when you answer it or settle it.

Press ⌘ ⌥ U (Ctrl Alt U off a Mac) to go to the next thread that needs you.

## Answer from the command line

Run `wsp threads` to see which threads need you. Then answer a permission prompt:

```sh
wsp thread allow 1a2b3c4d
wsp thread deny 1a2b3c4d --reason "Run the tests in the api folder only."
```

`--reason` tells the agent what to do instead. A `wsp run` you watch in a terminal asks you there: type `y` to run the call or `n` to refuse it.

## Notifications

When a thread asks something and the wsp window is not in front, wsp sends a notification titled "wsp needs you". Click it to open the thread. To change it, open **Settings > General > When a thread needs you** and pick **Off**, **Notify**, **Sound** or **Notify and sound**, the default.

On a Mac the menu bar and the Dock also show threads that wait on you. See [The desktop app on a Mac](/features/desktop-app).
