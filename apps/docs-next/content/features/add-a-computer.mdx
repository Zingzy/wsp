# Add a computer, and what it copies

You can add a Linux computer that you reach over ssh, such as a server you rent. wsp installs itself there with the agents, tools and settings you pick. Threads then run on it as they do on your computer.

<video src="/shots/setup.mp4" autoPlay muted loop playsInline aria-label="Add a computer from the first step to a computer ready for threads, with the setup rows filling in" />

For a computer you cannot reach over ssh, see [Computers behind a firewall](/features/behind-a-firewall).

## What the computer needs

- Linux on an `x86_64` or `aarch64` chip, with systemd and cgroup v2.
- A login that runs commands as root: `root`, or sudo. wsp does not keep a sudo password.
- Free disk for the base tools and 1 GiB more.
- A way back to the computer the app runs on, either directly or over ssh.

The **Checks** step tests these first.

## Add it

1. Open **Settings > Computers** and click **Add a computer**.
2. Type a login such as `root@203.0.113.7` or an ssh alias, or pick a host from your ssh config. Click **Connect**, or **Trust and connect** for a new host key.
3. Go through the steps and pick what goes on the computer.
4. On **Summary**, check the disk your picks need. To reuse the picks, tick **Save as a recipe**. See [Recipes](/features/recipes).
5. Click **Set up**.

## How sign-ins travel

For each agent you choose:

- **Copy the key.** The key stays on your host, and each turn on the new computer gets it in its environment. Nothing is written there. This shows only when your host holds the key. See [Agents and sign-ins](/features/agents).
- **Sign in on** the new computer. wsp runs the agent's own login there and shows it to you.

For GitHub, you can also **Skip for now**. Private repos then do not clone until you sign in.

## What an imported project carries

The new computer clones each project from its `origin` remote. By default these go with it too:

- Git-ignored config files such as `.env`, `.npmrc` and `*.pem`. They can hold secrets.
- The project's Claude Code memory folder.
- Commits the remote does not have.

To pick file by file, add the project from a terminal:

```sh
wsp add ~/code/lab --on studio
```

wsp lists the files and sends nothing. Run it again with `--yes` and any of these:

| Flag | What it does |
|---|---|
| `--cut <path>` | Leaves one path behind. Give it once per path. |
| `--keep <path>` | Sends one more path from the list. Give it once per path. |
| `--no-memory` | Leaves the Claude Code memory behind. |
| `--no-commits` | Leaves the unpushed commits behind. |
| `--remember` | Keeps these choices for the next add of this folder. |

## What never travels

These never leave your computer:

- Your agents' sessions and history. wsp reads only tool names and command words from them.
- Login files such as `.credentials.json`, `.git-credentials` and `.netrc`.
- Build output and caches such as `node_modules` and `.venv`.
- From your git config: credentials, signing keys, and settings that run a program on your computer.
- From your shell config: history, and exported variables named like secrets.

wsp never overwrites a file already on the new computer.

## From the command line

```sh
wsp add root@203.0.113.7
wsp add root@203.0.113.7 --recipe build-box
wsp add studio --resume
```

| Command | What it does |
|---|---|
| `wsp add <login or ssh alias>` | Adds the computer. Without `--recipe`, it joins and waits for its picks while the base tools go on. |
| `--recipe <name>` | Puts the recipe's picks on the computer. |
| `--name`, `--ssh-port`, `--ssh-key`, `--host-key` | Name the computer and say how to reach it over ssh. |
| `wsp add <computer> --resume` | Goes on with an add that stopped. |
| `wsp add <computer> --sign-in <agent>` | Runs an agent's sign-in on that computer. |

See [`wsp add`](/reference/cli/add) for every flag.
