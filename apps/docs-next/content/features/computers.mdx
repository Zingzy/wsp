# Computers

A computer is one of your own computers that wsp runs threads on. It is the computer the app runs on, or a Linux computer you added or joined. **Settings > Computers** lists them all.

<Image src="/shots/computers.webp" alt="Settings > Computers: the computer the app runs on and two added computers, each with its cores, memory, threads and state" caption="Settings > Computers." />

## The list

Each row shows the computer's name, its cores, its memory, its threads and its state. The computer you added last carries the tag `default`. A command that names no computer means that one. A thread always starts on its project's computer. Below the list, **Pending** holds the adds you have not finished.

| State | Meaning |
|---|---|
| Ready | The computer runs threads. |
| Setting up | Its setup runs now. |
| Needs you | A sign-in waits for you, or a project or the GitHub sign-in failed. |
| Setup failed | The setup stopped. The hover says why. |
| Behind | A change to its recipe is on its way. The hover names the changes. |
| No answer, or Stopped | The computer does not answer, or wsp on it stopped. |
| Blocked | It cannot run threads. The hover says why. |

A computer with an older wsp shows an **Update** button in place of a state. A computer where an agent has no sign-in shows **Sign in**.

To add a computer, click **Add a computer**. See [Add a computer](/features/add-a-computer), or [Computers behind a firewall](/features/behind-a-firewall) for a computer that dials out to you.

## A computer's own page

Click a row to open the computer's page. It shows the computer's version, system, cores and memory, then these parts.

### Update

If the computer runs an older wsp than the host, click **Update wsp on** the computer. Running threads carry on.

### Recipe

**Follows a recipe** names the recipe the computer follows, or **None**. A change to that recipe reaches the computer by itself. See [Recipes](/features/recipes).

### Setup and sign-ins

**Setup** lists what the setup put on the computer. **Sign-ins** lists each agent's sign-in there, with **Sign in** for one that is missing.

### Limits

| Setting | What it does | Default |
|---|---|---|
| Threads at once | How many threads run at the same time. New threads wait past this number. A thread that a running thread waits on runs in that thread's place. | One thread for every 2 GB of memory, at least 1 and at most twice the cores |
| Nap a quiet workspace after | A workspace with no running turn stops, and wakes on the next message. | 20 minutes |
| Turn limit | Stops a turn that runs this long. Send to the thread to continue where it stopped. Up to 24 hours. | Off |

When a computer is full, the next thread waits and starts by itself when a slot frees. Its transcript says so, with a **Raise threads at once** button that opens this page.

### Threads here

**Agents may start agents** lets a thread here start threads of its own. **Levels deep** sets how far, 2 by default. See [Leads and sub-threads](/features/leads).

### Name and ssh login

Click **Change** beside **Name** to rename the computer. You cannot rename the computer the app runs on.

Click **Change** beside **SSH login** to give wsp another login, as `user@host`. wsp saves it only if it reaches the same computer.

### Remove

Click **Remove** and confirm. The computer's threads leave the host, and your files there stay. If a project there holds work that no remote has, the dialog names it, and the button says **Remove anyway**.

For a computer you added over ssh, wsp logs in and takes its own service and files off.

The wsp service stays on the computer, running as root, if the computer joined with a code or was offline when you removed it. Then run `wsp leave` as root on that computer. See [Computers behind a firewall](/features/behind-a-firewall#take-a-computer-out).

## From the command line

`wsp computers set` changes one computer:

```sh
wsp computers set studio --threads 6 --turn-limit 4
wsp computers set studio --name lab-box --ssh root@203.0.113.7
wsp computers set studio --recipe build-box
```

| Flag | What it sets |
|---|---|
| `--name <new>` | The computer's name. |
| `--ssh <login>` | Its ssh login. |
| `--threads <n>` | Threads at once. |
| `--turn-limit <hours>` or `off` | The turn limit. |
| `--nap <minutes>` or `off` | The nap of a quiet workspace. |
| `--spawn on` or `off` | Whether a thread there can start threads. |
| `--max-depth <n>` | How many levels deep. |
| `--recipe <name>` or `none` | The recipe it follows. With `none`, the computer keeps what it has. |
| `--reset <setting>` | Puts a setting back to its default. |

`wsp remove <computer>` takes a computer out. It asks once. `--force` removes it even when it holds work that no remote has, and that work is lost.

See [`wsp computers`](/reference/cli/computers), [`wsp computers set`](/reference/cli/computers-set) and [`wsp remove`](/reference/cli/remove) for every flag.
