The Changes pane shows the git changes in the thread's folder. You can read the diff, comment on lines, edit or discard a file and commit, without leaving the app.

To open it, click **Add a panel**, the **+** at the top of the right panel, and pick **Changes**. If the right panel is empty, pick it from the list there. In that menu or that list, `D` picks it too. You can also click **Open diff** on a turn's list of changed files.

## Pick what to compare

The scope menu at the top of the pane has four choices:

| Scope | What it shows |
|---|---|
| Branch changes | Everything on the branch since it left the default branch, committed or not. This is the default. |
| Uncommitted | Every change since the last commit. |
| Working tree | The changes that are not staged. |
| Staged | The changes that are staged. |

Branch changes and Uncommitted also list new files that git does not track yet.

## Read the diff

At the top is a tree of the changed files, with a count such as `3 of 7 viewed`. The diff is under it.

- **Stacked view** and **Split view** switch between one column and old beside new.
- Tick a file as viewed to fold it until it changes again.
- Click the pin, **Stay in this folder**, to stop the pane following the agent to another folder.

## Comment on lines

Select one or more lines and type a comment. Click **Send to thread** at the top of the pane to put your comments into the composer as a draft.

## Edit or discard a file

Click the edit button on a file to change it in place, then click save.

To throw away the changes to one file, click its trash icon and confirm. The file goes back to its last commit, or is deleted if no commit has it. A discard cannot be undone.

## Commit

1. Pick the **Uncommitted** scope.
2. Click **Commit**. Every changed file is ticked.
3. Untick the files you want to leave out.
4. Read the message the agent drafted from the diff, and change it if you want.
5. Click **Commit**.

The commit runs the folder's git hooks, and stops if one fails. Nothing leaves the computer until you push.

## Push and open a pull request

The git button in the thread's top bar does the next step for the folder, such as **Commit and push**, **Push and create PR** or **View PR**. Its menu, **More git actions**, has the rest.

**Commit and push** and **Commit, push and PR** commit every changed file with the agent's message, without showing you either. To pick the files, commit from the Changes pane first. The [pull request pane](/features/pull-requests) then shows the pull request.

## A turn's changed files

Under each turn, the thread lists the files that the turn changed. Click **Open diff** to see them in the Changes pane.

## From the command line

| Command | What it does |
|---|---|
| `wsp commit <thread> [--message "<message>"] [--file <path>]...` | Commits the changed files, or only the ones that `--file` names. Without `--message`, the agent drafts the message. |
| `wsp discard <thread> <path> [--yes]` | Puts one file back as its last commit has it. It asks first, unless you pass `--yes`. |
| `wsp update <thread>` | Merges the newest commits of the base branch from the remote into the branch, with a merge commit. |

`wsp update` never rewrites a branch. If the folder has uncommitted changes or the merge conflicts, it stops and names the files. [`wsp fix`](/reference/cli/fix) hands a conflict to the agent. None of these commands pushes.

The command line reference has every flag: [commit](/reference/cli/commit), [discard](/reference/cli/discard) and [update](/reference/cli/update).
