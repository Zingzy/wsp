# Threads

A thread is one conversation with a coding agent in one project, and a row in the sidebar. Each message you send starts a turn, one run of the agent's process for that message.

<Image src="/shots/docs-composer.webp" alt="The sidebar with a lead and its sub-threads, beside the lead's thread: its transcript, and the composer below it with the model and effort pickers" caption="A lead's thread beside its tree in the sidebar, with the composer at the bottom." />

## Send a message

Type in the composer and press Enter. Shift+Enter makes a new line. To send with ⌘ Enter instead (Ctrl Enter off a Mac), set **Send with** in **Settings > General**.

The up and down arrows at the edge of the box walk through your earlier prompts. ⌘ S (Ctrl S off a Mac) stashes the draft, and brings it back in an empty box.

## Send while the agent works

While a turn runs, **Send** becomes **Stop**, and the send key still sends. What happens then depends on **Settings > General > A message while a thread works**:

- **Queue**, the default, holds the message until the turn ends, then starts the next turn with it.
- **Steer** hands the message to the agent at its next tool call, and the reply comes in the running turn. It works only for an agent that takes a message mid-turn and a message with no files. Otherwise the message queues.

Waiting messages show in a row above the composer. Click it to **Edit** or **Cancel** each one.

## Mentions and commands

In the composer, `@` lists the files in the thread's folder, `#` the open pull requests and issues, and `$` the agent's skills. `/` at the start lists the agent's own commands, plus wsp's `/btw`, which asks a [side question](/features/side-question).

## Attach files

Paste a file, drop it on the thread, or click the paperclip. One message takes at most 5 files of up to 10 MB each:

| File | Where it goes |
|---|---|
| PNG, JPEG, GIF or WebP image | To the agent, as an image |
| Any other file | Into `.wsp-files/` in the thread's folder, which git ignores. The message tells the agent where. |

A long paste becomes a file. Some agents take no image, so describe it in words or switch agents.

## Pick a model and effort

The pickers under the box set the model and effort for the next turn. The lists come from the agent itself, so they change with each release.

## Read the turn line

While a turn runs, the line at the end of the transcript says "Working for", or "Waiting for you" while the turn waits on a [prompt](/features/needs-you). When the turn ends, its steps fold into one line. Click it to open them.

## Stop a turn

Click **Stop**, the red square in place of **Send**, or run `wsp stop <thread>`. The thread stays. Stopping a lead stops every thread under it too. See [Leads and sub-threads](/features/leads).

## Titles

wsp titles a new thread from its opening message, and never replaces a title you gave. To rename a thread, double-click its title, or run `wsp thread rename <thread> "<title>"`.

## From the command line

`wsp run` opens a thread and sends its first message. `wsp send` sends a message into a thread you have:

```sh
wsp run lab "Fix the flaky login test."
wsp send 1a2b3c4d "Also cover the codex case in the test."
```

A send is never refused because a turn runs. Its `outcome` under `--json` is one of:

| Outcome | When |
|---|---|
| `started` | No turn ran. The message starts a new turn. |
| `steered` | The message joined the running turn. |
| `queued` | The agent takes no message mid-turn. The message runs as the next turn. |
| `held` | The computer runs as many threads as it allows. The turn starts when one ends. See [Computers](/features/computers). |

The command line steers whenever the agent can. The **Queue** setting changes only the app.

Every flag is on the [`wsp run`](/reference/cli/run), [`wsp send`](/reference/cli/send) and [`wsp stop`](/reference/cli/stop) pages.
