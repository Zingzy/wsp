# The browser pane

{/* Written from apps/web/src/components/preview/, apps/web/src/browser/ (refusal.ts, url.ts, loopbackLinks.ts), daemon/crates/wsp-daemon/src/ports.rs, packages/runtime/src/places/pane-ports.ts. */}

The Browser pane shows a web server that runs on the thread's computer, beside the thread. Use it to look at your dev server while the agent works on it.

To open it, click **Add a panel**, the **+** at the top of the right panel, and pick **Browser**. If the right panel is empty, pick it from the list there. In that menu or that list, `B` picks it too. You can also press `mod+shift+j`.

## Open a server

The pane lists the servers that listen on the thread's computer under **Local servers**, and the addresses you opened before under **Recently used**. Click one to open it. On a computer you own, the list holds only the ports of this thread's work.

To open a port that is not in the list, type it in the address bar: `3000`, `:3000`, `3000/about` or `localhost:3000/about`. The pane opens only ports on the thread's computer.

## A thread on another computer

For a thread on a computer you added, wsp forwards the port to `localhost` on the computer you sit at. It keeps the port number if it is free. Ports below 1024 are not forwarded. A forward closes when nothing uses it for a while. Open the address again to forward it again.

While wsp forwards a port, **Open on laptop** opens it in your own browser. A link to `localhost` in a reply opens in a Browser tab too.

## The controls

The bar has **Back**, **Forward**, **Refresh**, **Open in system browser** and **Copy URL**. The **More** menu adds **Hard reload**, **New tab**, and the page zoom.

The pane has no developer tools. To use them, click **Open in system browser**.

## When the page is white

A dev server often refuses a host name it does not know, and the pane then shows a white page. For a thread that is not on the computer you sit at, the pane checks what the server answered. If the server refused the host, the pane names the fix:

| Server | What the pane says to do |
|---|---|
| Vite | Restart the dev server so that it picks up the allowance that the thread's environment already sets. Or add the host to `server.allowedHosts` in `vite.config`. |
| webpack-dev-server | Add the host to `devServer.allowedHosts` in the webpack config, or start it with `--allowed-hosts <host>`. Then restart it. |
| Rails | Add `config.hosts << "<host>"` to `config/environments/development.rb` and restart the server. |
| Next.js | Add the host to `allowedDevOrigins` in `next.config` and restart it. |

For any other server that refuses, allow the host in its config and restart it. If a fix does not apply, read the server's own log.
