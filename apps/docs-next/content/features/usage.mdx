Settings > Usage shows the tokens your agents used and what they cost at list price, split by agent, account, computer, project or model. Its **Limits** tab shows how much of each plan's limits your accounts have left.

<Image src="/shots/usage.webp" alt="Settings > Usage: tokens a day by agent, and the table by agent and model." />

## What wsp counts

wsp counts the tokens of every turn it ran. It also reads the logs Claude Code, Codex and OpenCode keep on each of your computers, so the page counts work you did with those agents outside wsp too. To stop that, turn off **Agent logs** in Settings > Privacy.

The cost is an estimate at the list price in LiteLLM's public price table. A model missing from it shows **not priced**. On a plan, you pay the plan's price, not the list price.

## The Usage tab

Pick a range, **Today**, **7 days** or **30 days**, and how to split it. The top row shows:

| Figure | What it is |
|---|---|
| Tokens | The input and output tokens in the range. |
| API estimate | The cost at list price. |
| Turns | How many turns ran in threads wsp ran. |
| Cache hit | The share of input read from the cache, and what it saved. |

Under it are a chart of tokens over the range, a table with a row for each agent or whatever you split by, and **Where the tokens went**.

## The Limits tab

Each agent has a card with its accounts that run on a plan. Each card shows how much is left in each plan window, such as **5-hour** and **Week**, how fast your threads use tokens now, and when the window resets or runs out.

wsp reads these figures from the last turn it ran on that account. An account with no turn yet says **not read yet**. An account signed in with an API key says **pays per token, no plan limit**.

### Use a banked reset

A Codex account can bank resets. If it has one, the card offers **Use reset**, which starts the 5-hour and weekly windows again now. There is no undo. From the command line, run `wsp usage reset <account>`. An agent in a thread cannot run it.

## When a plan runs out

If a plan limit stops a turn, a bar in place of the composer says **Usage limit reached**. If the agent said when its plan resets, click **Resume at reset** and the thread goes on by itself at the reset.

wsp also sends a notification at 70% and 90% of a window and when an account reaches its limit. To turn these off, use **When a plan window runs low** in Settings > General.

## From the command line

```sh
wsp usage --range week --by model
```

`--range` takes `day`, `week` or `month`. `--by` takes `agent`, `account`, `computer`, `project`, `model` or `source`, which splits wsp's threads from the work the agents logged outside wsp. Only `--by source` reads the agents' own logs, so `wsp usage` can show less than Settings > Usage for the same range.

See [`wsp usage`](/reference/cli/usage) and [`wsp usage reset`](/reference/cli/usage-reset).
